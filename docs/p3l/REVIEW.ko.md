# 통합 검수 및 수정 기록

검수 책임자는 Codex다. 작업자별 Draft PR의 최종 커밋, 실제 검사 결과, 의존 변경을 먼저 확인한다. 수정 방향은 아래에 버전별로 기록하고 작업자 PR에 연결한다. 리뷰로 바뀐 기준이 있으면 바뀐 부분과 적용할 다음 작업을 함께 적는다.

## v1 · P3k를 바탕으로 잡은 수정 방향

| 검수 대상 | 현재 결정과 근거 | 적용 대상 |
| --- | --- | --- |
| 원장 계약과 모델 입력 | 빈 목록과 빈 원소를 사례와 함께 구분한다. P3k가 목록 수준의 거부만 추가해 기존 정상 사이클이 실패했다. | W01, W02 |
| 진단과 고정 채점 | 고정 25개를 보존한다. `change` 검사에 정상 `fixes`를 사용하는 등 규칙이 섞이는 부분은 별도 진단에서 확인한다. | W03, W05, W06 |
| 반복 후보 | 동일 함수 AST의 재출현을 후보 테스트 전에 막는다. 과거 모델 응답은 대조 증거로 유지한다. | W04, W06 |
| 승격과 후속 개발 | 후보 25/25, 독립 재검증, 그 소스 커밋에 대한 전체 CI를 차례로 확인한 뒤 실행기 전환과 복구를 검수한다. 후속 패치는 전환된 버전에서 별도로 검증한다. | W05, W07, W08 |

P3k의 후보는 20/25였고 독립 러너가 실패를 재현했다. 실험 브랜치의 Harness CI 675개 통과는 모델 후보의 합격 점수와 별개다. [P3k 검수 근거](https://github.com/js775315672-spec/Harness-Ouroboros-MCP/pull/36)

## 후속 검수 기록 방식

각 리뷰에 아래 항목을 남긴다. 여러 작업이 같은 파일이나 계약에 걸치면 Codex가 변경 순서를 정하고 통합 브랜치에서 최종 수정과 전체 검사를 수행한다.

```markdown
## v[번호] · [작업 ID 또는 통합 영역]
- 작업자 PR, 검수 커밋, 증거 링크
- 판정과 관찰 근거
- 필요한 수정 범위와 담당 작업
- 통합 커밋과 다시 실행한 검사
- 남은 차단 조건과 다음 작업자에게 바뀐 기준
```

현재 기준은 v1이다. 작업자별 결과 검수와 통합 구현 판정은 PR과 실행 기록이 제출되는 시점에 추가한다.
