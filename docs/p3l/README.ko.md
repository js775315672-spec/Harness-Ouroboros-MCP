## 작업과 보고 방식

계획이 올라간 브랜치에서 `work/p3l-w01`부터 `work/p3l-w08` 중 자기 브랜치를 만든다. 다른 작업의 결과에 의존하면 보고에 해당 PR과 커밋을 기록한다. 각 작업은 계획 브랜치를 대상으로 Draft PR 하나를 열고 제목을 `[P3L W01] 변경 요약` 형식으로 작성한다. 공용 파일이 필요하면 자기 PR에 수정 제안과 충돌 지점을 적는다. 공용 실행 진입점과 승격 설정은 Codex가 통합하면서 최종 수정한다.

아래 항목을 각 Draft PR 본문에 남긴다. 실행하지 않은 검사는 `미실행`과 이유를 기록하고, 로그 링크는 해당 커밋의 실행을 가리킨다.

```markdown
## 작업 보고
- 작업 ID 및 기준 커밋
- 변경한 파일과 동작
- 재현 명령, 실제 결과, CI 또는 기록 링크
- 실패한 사례와 남은 제약
- 다른 작업자에게 필요한 인터페이스나 결정
- 통합 시 추천하는 수정과 그 근거
```

## 통합 검수

Codex가 각 PR의 코드, 증거, 테스트를 대조하고 공용 파일의 충돌을 해결한다. [검수 및 수정 기록](REVIEW.ko.md)에 수용·수정 요청·보류와 이유, 통합 변경, 다시 실행한 검사, 다음 작업자에게 적용할 기준을 남긴다. 통합 대상 PR에는 해당 결정의 링크를 추가한다. 최종 검수는 기존 회귀, 고정 후보 검사 25개, 별도 러너 재검증, 승격·복구와 후속 작업 실행 순으로 진행한다.

모델 후보의 소스에 사람이나 검수자가 추가 수정한 경우 검수 기록에 수정 주체와 새 SHA를 남긴다. 모델 출력의 합격 기록은 원래 후보 SHA로 유지한다.
