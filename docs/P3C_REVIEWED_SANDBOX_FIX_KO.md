# P3c — 실제 sandbox_policy.py 권한 검증 보안 수정 (AI 단독 수정 실패 후 검토·보완)

2026-11-16 · Draft · 기존 코드 수정 성공 여부는 해당 GitHub 커밋 전체 CI로 판단

## 실증된 기존 보안 결함
원본 scripts/sandbox_policy.py는 workflow_permissions를 입력으로 받아 read 권한인지를 검사한 다음 **검사받은 바로 그 사용자 dict 객체를 반환**했다. 따라서 호출자가 입력 객체를 검사 후 변경하면 반환된 read-only 명세도 바뀐다. 또한 dict의 하위 클래스가 __ne__ 연산을 재정의해 False를 반환하는 경우, 쓰기 권한 또는 추가 scope가 있어도 비교 연산이 거짓으로 나와 검증을 우회할 수 있다.

실제 실행 샌드박스와 별개로, 이는 후속 코딩 에이전트용 보안 명세의 신뢰성이 변질될 수 있는 문제다.

## P3c 코드 수정: 사람의 검토를 거친 별도 비자율 패치
실제 scripts/sandbox_policy.py:policy를 수정하여:
1. workflow_permissions=None은 신규 안전한 read-only 권한 dict 생성.
2. 명시 입력은 정확히 built-in dict 타입이고 값이 정확히 {"contents":"read"}일 때만 통과. dict 하위 클래스나 추가 권한은 무조건 거부.
3. 검증 성공 시 원래 입력 객체를 반환하지 않고 **별도의 신규 dict** 생성. 호출자가 원본을 변경해도 반환 명세는 변하지 않음.
4. 원래 handoff/승인/권한 차단 플래그와 기존 반환 필드 유지.

tests/test_sandbox_policy_security_p3c.py에는 P3a 당시 사전 동결했던 **10개 보안 테스트를 바이트 그대로 복사**했고, 별도 정답을 보고 테스트 기대값을 수정하지 않았다. 소스와 테스트의 빌드 뒤 전체 Harness CI를 확인해야 한다.
