# P2a — 실제 저장소 소스 패치 실험 (2026-11-16)

## 문제: 기존 소스의 검증되지 않은 작업 지시 문구
대상은 실제 모듈 **scripts/agent_handoff.py**의 handoff(proposal, branch) 함수다. 원본은 작업(task)이 비어있지 않은 문자열인지 확인하지만, NUL/ESC/개행/탭/DEL/C1 제어문자, 앞뒤 공백, 과도한 UTF-8 길이를 충분히 제한하지 않는다. 향후 외부 코딩 에이전트가 작업 문구를 소비할 때 신뢰 경계가 흐려지는 위험을 축소하려는 목적이다.

### 기존 성능과 새 단계의 차이
P1d와 P1e의 검증된 고유 함수 생성 결과는 각 **2/8**이었다. 그러나 두 실험 모두 solve(data)라는 작은 독립 함수였으며 저장소 개발 사이클을 생성하지 않았다. **P2a는 실제 기존 모듈의 함수 구현 전체를 모델이 다시 작성한 뒤, 동일 저장소의 협력 모듈과 함께 검증한다.**

## 고정된 과제·평가
- 기존 모듈: scripts/agent_handoff.py — 모델 입력으로 실제 기존 handoff 함수 코드 제공.
- 허용된 수정: 기존 handoff 함수의 소스 구간 **한 곳만**. 다른 import, SAFE_BRANCH 정규식, 다른 함수, 다른 파일을 모델이 수정할 수 없다.
- Qwen2.5-Coder-7B-Instruct GGUF 4bit, 1회 호출, 출력 최대 6,000바이트, 토큰 예산 800, CPU 호출 최대 240초.
- 기존 회귀 테스트 **13개**: tests/test_agent_handoff.py (7), tests/test_sandbox_policy.py (6). 원본에서 모두 통과해야 한다.
- 새로운 숨겨진 보안 테스트 **10개**: tests/heldout_p2a_agent_handoff.py. 원본에서는 최소 하나 실패해야 하며, 모델은 이 파일을 보지 못한다.
- 최종 성공 조건: 동일한 신뢰 테스트 23개를 모델 수정 버전이 모두 통과하고, 다른 GitHub 러너에서 모델 원본 출력·패치 SHA·커밋 SHA를 대조해 동일한 결과 재현.
- 실패를 자동 수정하지 않는다. 모델 출력이 실패해도 실패로 기록한다.

## 실행 및 보안 경계
- 실제 체크아웃은 **읽기 전용**이며 GitHub Actions 자격증명 저장 금지, 권한 contents:read.
- 원본 및 후보 모듈은 /tmp의 복사본에만 생성하고, 네트워크 차단·읽기전용·비루트·CPU/메모리 제한 Docker에서만 후보 코드를 실행한다.
- 모델 답변 전체와 단일 함수 교체에서 유도된 **실제 unified diff**를 산출물로 남긴다.
- 현재 실험 자체는 모델로부터 저장소에 소스 커밋을 작성할 권한이 없으며, 자동 푸시/병합/재귀 실행·일정 실행을 하지 않는다.
- 따라서 모델 패치가 격리 회귀 테스트를 통과하더라도 **GitHub SHA에 패치 커밋이 포함되어 독립 CI를 통과할 때까지 '자율 개발 완료'라고 표현하지 않는다.**
- 병합은 계속 사람의 명시적 승인이 필요하다.

## 결과 해석
- 모델 호출 성공 ≠ 소스 패치 성공.
- Docker 테스트 통과 ≠ 실제 저장소 커밋 생성.
- Draft PR의 녹색 Harness CI ≠ 모델 결과 합격.
- 합격한 경우에만 별도로 소스 패치 후보를 검토해 Draft PR 브랜치에 반영하고 정확한 SHA의 전체 CI와 독립 검증을 다시 확인해야 한다.
