# P1e 신규 8개 과제 · 실증 연구 계약 (2026-11-16)

## 변경 불가 기준선
P1d의 [고정 실험 실행 #43834933312](https://github.com/js775315672-spec/Harness-Ouroboros-MCP/actions/runs/43834933312): **8개 서로 다른 과제에서 실제 모델 호출 8회, 후보 합격 2/8(25%), 후보 실패 4/8, AST 거부 2/8**, 독립 재생 8/8, 고유 합격 소스 2개. 이는 P1e 실험을 성공이라고 선포하는 근거가 아니다.

### 원본 불합격의 확인 가능한 유형
- 01: `bool`이 `int`의 하위 타입임을 고려하지 못해 `True`를 유효한 정수로 계산.
- 02: 잘못된 공백/빈 문자열을 받아들임.
- 04: 부모 목록 길이를 `==8`로 가정, 실제 계약은 1~8.
- 05: 허용되지 않은 메서드 호출로 AST 검증 거부.
- 06: `..` 및 빈 경로 구간을 제대로 거부하지 못함.
- 07: 금지된 람다/내포 표기를 생성하여 정적 검사 거부.

## 새로운 과제와 독립 홀드아웃
P1e는 8개의 **새로운 함수 명세**를 사전에 잠근다. 단계가 유사해도 필드 이름, 기능, 경계 값, 조건, 목적, 검증 데이터가 P1d와 다르다. 옛 파일 `tests/heldout_p1d.py`는 변경하지 않는다.

각 레인은 프롬프트로 명세를 받으며, `tests/heldout_p1e.py`의 **9개 동작 + 1개 비변경성 검사**는 보지 못한다. 한 번의 Qwen 7B 호출만 허용하며 재시도, 정답 코딩, 출력 후 자동 보정은 금지한다. 모델 답안 자체는 (정확한 Python Markdown 테두리만 허용) 정적 AST/경계 검사를 거친다.

**필수 실행 게이트:** 부정대조군이 동일한 10개 테스트에서 실패 → 후보가 동일한 10개를 완주 → 네트워크 차단·읽기전용·비권한 Docker 실행 → 다른 GitHub Actions 러너에서 원본 모델 응답 해시와 불변 SHA, 홀드아웃 해시를 대조하고 재실행. 과제별 실패는 그대로 보존한다.

## 성공 측정
- 실제 독립 호출 수: 모든 8개 레인을 고정 분모로 기록.
- 합격 후보 수: 독립 재생 성공의 교집합만.
- 고유 소스 수: 정규화 후 함수 코드 SHA-256 중복 제거.
- 커밋 반영 완료: **0**. 일반 코드 변경 에이전트의 성공도 아직 증명되지 않음.
- 1차 과제의 2/8과 2차 P1e의 합격률은 난이도·평가 집합이 달라 **인과적 성능 개선률로 비교 불가**.
