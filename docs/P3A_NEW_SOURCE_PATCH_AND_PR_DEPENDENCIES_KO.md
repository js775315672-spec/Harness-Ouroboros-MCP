## 1. 실험 목적과 신규 결함
대상은 앞서 P2a~P2d에서 다룬 agent_handoff가 아닌, 실제 운영 정책 모듈 **scripts/sandbox_policy.py:policy**다. 기존 구현은 입력이 단순 dict인지 확인하고 {"contents":"read"} 값과 동등한지 검사하지만, 입력 객체 자체를 결과에 반환하고 dict 하위 클래스의 사용자 정의 비교 메서드가 신뢰 판단을 조작하는 문제를 갖는다.

발견된 구체적 오류:
- 통과한 뒤 호출자가 제공한 dict를 {"contents":"write"}로 변경하면 결과의 github_token_permissions가 같이 바뀜(TOCTOU/alias).
- dict 하위 클래스가 __ne__ 비교를 오버라이드해 False를 반환하면 contents:write 또는 추가 permission을 가진 객체가 동등한 read scope처럼 검사될 수 있음.
- 정책은 실행 샌드박스가 아닌 **읽기 전용 정책 명세**임. 모델이 실제 GitHub Actions write scope를 획득하는 것이 아님.

- 사전 허가된 수정 영역: **기존 policy(proposal,branch,workflow_permissions=None) 함수 블록 단 하나**. 모듈 import·전역 변수·다른 함수·기존 테스트 수정 금지.
- 기존 회귀 23개: test_agent_handoff.py 7개, test_sandbox_policy.py 6개, P2d의 사전 동결 보안 회귀 10개. 원본에서 23/23 통과 필요.
- 새 보안 홀드아웃 10개: caller alias, 사후 권한 변조, 비교 연산 스푸핑, dict 하위 클래스 검증, 읽기 전용 기본값, 추가 scope·입력 변조 검사. 원본에서 반드시 하나 이상 실패해야 하고, 모델은 홀드아웃 테스트 코드에 접근하지 않음.
- 모델이 새 10개를 포함한 **33/33** 및 기존 코드 계약을 성공시켜야 모델 단독 수정 후보 합격.
- 후보는 기존 파이썬 소스 블록 단일 교체로 실제 unified diff 산출; 모델이 원본 checkout에 직접 쓸 수 없음. 메타데이터에는 원본 SHA·홀드아웃 SHA·모델 프롬프트 SHA·모델 원본 응답 SHA·후보 소스 SHA를 기록함.
- 임시 원본·후보 복사본에 대해 네트워크 차단, 읽기 전용, 비루트 Docker에서 모든 테스트를 실행하고, 별도 GitHub Actions 러너에서 후보 전체를 독립 재생.
- **모델이 실패하면 새로운 candidate_acceptance_gate가 실패함.** 인프라 작업 녹색을 모델 소스 합격으로 혼동하지 않음.
