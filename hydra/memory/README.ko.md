# Hydra 검증 경험과 9회 연속 캠페인

## 기록과 재사용

- 운영 원장과 Actions 원본은 실행의 출처다. `hydra/memory/history.json`은 비교 가능한 항목으로 정리한 파생 기록이다. 원본 산출물, 거부 결과, 작업 승인, 실제 배포는 각 상태를 분리한다.
- 주기마다 문제 ID, 기준·후보·운영 SHA, 모델 실행과 독립 판정, 운영 후속 검사, 실패 실행, 롤백 종류, 개선 전후의 테스트·측정 범위, 다음에 적용할 교훈을 남긴다. 합격 후속 실행까지 확인된 주기만 완료로 센다.
- 새 과제에 관련 주제의 합격 교훈을 제공한다. 실행 근거와 과제 설명을 함께 전달하며 원시 모델 출력, 비공개 검증 데이터, 비밀정보는 검색 결과나 모델 입력에 넣지 않는다. 같은 입력의 중복 추론은 금지한다.
- 운영 기록의 `generated_code_merged`와 `rollback.production_observed`는 실험 결과와 실제 반영·복구를 분리한다. 게이트에서 거부된 후보는 운영 롤백 건수에 포함하지 않는다.
- 새 캠페인은 운영 합격을 독립 확인한 뒤 직전 기록과 다음 기록의 연결을 보존한다. 주기가 멈추면 마지막으로 증명된 상태에서 재개한다. 실패 시 같은 실행은 재호출하지 않고 입력이나 가설을 바꾸기 전 별도 증거를 남긴다.

## 지속 자기발전의 5단계

1. **관찰과 분류.** 실제 실패와 재현 증거를 연결하고 안정적 문제 ID를 사용한다. 중복 관찰 및 알려진 실패의 새 증거를 구분한다.
2. **제안과 안전한 실행.** 기존 Hydra 승인과 1회 원장으로 허용된 작은 가설을 실행한다. 실패는 예산을 다시 열지 않는다.
3. **독립 검증과 비교.** 같은 기준·러너·바이너리·동일 테스트로 A/B 실행을 반복해 중앙값, p90, 실패율을 비교한다. 검증된 산출물만 다음 과제로 연결한다.
4. **기억 기반 다음 선택.** 합격 교훈을 검색하고 대응 가설의 성공률을 추적한다. 이전 가설을 재사용할 때 출처와 적용 제한을 기록한다. 자동 선택은 고정 위험·범위·비용 한도를 따른다.
5. **지속 반복.** 실제 운영 증거로 중단·복구·운영 후속까지 포함하는 연속 9주기를 검증한다. 독립 실패·비용 초과·증거 누락 시 중단한다. 새로운 평가 조건을 통과해야 자동화 범위를 늘린다.

## 속도 개선 우선순위

검증한 바이너리의 SHA와 모델 revision을 유지하며 재사용한다. 기준선 준비와 증거 조회는 독립 실행이 가능한 경우에만 병렬화한다. 준비, 모델, 독립 판정, 운영 후속을 따로 시간 측정한다. 성능 비교는 동일 작업과 동일 조건에서만 수치화한다. 독립 검증은 생략하지 않는다.
